# 第 2 周：用本地模型构建最小 Coding Agent

## 目标

沿用第 1 周的 Ollama 与 `qwen3:4b`，实现一个范围受控的 Agent 循环：模型接收用户请求，必要时请求调用你定义的本地工具，程序执行工具并把结果交回模型。你需要区分“模型提出了工具调用”和“程序确实执行并验证了工具”这两个状态。

## 环境

先完成第 1 周的安装和连通性检查。在本目录安装依赖：

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate
python -m pip install -r requirements.txt
```

确认 Ollama 服务已启动，且 `ollama list` 中包含 `qwen3:4b`。从 `../week01/.env.example` 复制 `.env` 到本目录，并按需设置 `OLLAMA_MODEL`。

## 作业任务

1. 阅读 `agent.py`，完成标有 `TODO` 的工具描述、输入校验、模型请求和循环控制。
2. 提供至少一个确定性、本地执行、作用范围明确的工具。工具输入必须经过类型和范围校验；模型输出不能绕过程序校验直接执行命令或修改文件。
3. 在 Agent 循环中限制最大轮数；正确处理模型不请求工具、请求未知工具、参数无效、工具报错和服务不可用等情况。
4. 设计不少于 5 个场景进行手动验证，包含至少 2 个预期调用工具的请求和 2 个不需要工具的请求。记录模型是否选对工具、参数是否有效、结果是否可信以及你如何处理失败。
5. 任选一个工具输入或返回值做边界测试，说明为何该检查应由程序负责，而不能只依赖提示词。

本周不要求模型输出固定措辞或固定推理过程。评分关注工具契约、控制流、错误处理和可复核的实验记录。

## 提交内容

- 完成后的 `agent.py`；
- `report.md`，记录模型标签、环境版本、验证场景与结果、已知限制；
- 如有必要，提供不含密钥和私人数据的运行截图或日志节选。

不要提交 `.env`、模型权重、密钥、完整私人会话或任何教师参考答案。
